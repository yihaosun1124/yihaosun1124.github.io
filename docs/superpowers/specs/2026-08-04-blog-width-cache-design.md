# Blog Width and Cache Consistency Design

## Goal

Make the blog visibly wider on desktop and prevent a newly deployed post from continuing to use stale HTML or CSS that hides the current MathJax and heading-alignment behavior.

## Observed Root Cause

- A fresh production-page inspection renders 10 MathJax containers, including one display equation.
- The fresh page computes `.post-content h1` as `text-align: left` and `.post-header h1` as `text-align: center`.
- GitHub Pages serves both the blog HTML and `assets/css/style.css` with `Cache-Control: max-age=600`.
- The stylesheet URL and homepage blog URL currently have no build-specific version, so an already cached response can remain visible for up to ten minutes after deployment.

The formula renderer and scoped heading rule are therefore working in the deployed code. The failure is stale deployed content in the client cache, not a MathJax parsing or CSS-specificity defect.

## Design

### Desktop Width

Change `.post` from `max-width: 900px` to `max-width: 1040px`. The existing `.site-shell` is already capped at `1040px`, so the post and homepage will share one desktop content boundary. Existing mobile padding and the `width: 100%` shell behavior remain unchanged.

### Cache Versioning

Use Jekyll's `site.time` as one build-wide version value:

- Append `?v=<build timestamp>` to the generated stylesheet URL in `_layouts/default.html`.
- Append the same version query to blog-post links generated by `_includes/blog.html`.

Every deployment will therefore produce a new CSS URL and a new homepage-to-post URL. This bypasses stale cached resources without adding JavaScript reload logic, changing canonical URLs, or altering GitHub Pages configuration.

GitHub controls the response cache headers, so a direct unversioned bookmark can still retain an old HTML response until its existing ten-minute cache entry expires. The canonical clean post URL remains unchanged; links generated by the homepage receive only a transient cache-busting query.

### Formula and Heading Behavior

Keep the current conditional MathJax 4 loader and the current `$...$` / `$$...$$` authoring contract. Keep `.post-content h1 { text-align: left; }` and `.post-header { text-align: center; }` unchanged. These behaviors have already been confirmed in a fresh production browser session.

## Files

- Modify `assets/css/style.scss` for the `1040px` post width.
- Modify `_layouts/default.html` for the versioned stylesheet URL.
- Modify `_includes/blog.html` for versioned post links.
- Create ignored temporary contract tests during implementation; remove them before the final commit.

## Verification

1. Write a failing temporary contract that requires a `1040px` post width and build-version queries in both generated URLs.
2. Build Jekyll and verify the contract passes.
3. In a fresh desktop browser, verify a `1040px` post, centered post title/date, left-aligned Markdown H1, and rendered inline/display MathJax.
4. At a `390px` viewport, verify no page-level horizontal overflow.
5. Push `master`, wait for the matching Pages workflow, and confirm the live versioned CSS/post URLs plus rendered production behavior.

## Non-Goals

- Replacing or self-hosting MathJax.
- Changing homepage width.
- Changing post typography, mobile breakpoints, canonical URLs, or content.
- Adding service workers, forced reloads, or custom cache headers unsupported by GitHub Pages.
